## TUI 交互模式

TUI（Text User Interface）模式是 Mini2FA 的主要交互方式，提供完整的图形化界面。

### 启动方式

```bash
# 直接启动（推荐）
mini2fa

# 禁用 TUI（纯文本输出，用于脚本/CI）
mini2fa --no-tui
```

**首次使用**会提示设置主密码：
```
首次使用，请设置主密码：
⚠️  请牢记此密码，丢失将无法恢复数据！

密码要求：至少 6 位，且包含大写字母、小写字母和数字

输入主密码: ********
确认主密码: ********
设置密码提示（用于忘记密码时提醒，可留空）: 我的宠物名字
✓ 主密码已设置成功！
```

**密码要求**：
- 长度 ≥ 6 位
- 必须包含大写字母、小写字母和数字
- 最多尝试 5 次

**密保提示**：
- 可选，用于忘记密码时提醒
- 存储在本地，不加密

#### 1. 添加账号（扫码图片）

从二维码图片添加 2FA 账号。

**操作流程**：

1. 选择 `1` 进入添加账号
2. 输入二维码图片路径（支持 Windows 拖拽文件，自动去除引号）
3. 系统扫描二维码，显示识别结果
4. 输入分类（可选，直接回车使用默认）
5. 输入备注（可选，最多 20 字）
6. 确认添加

**示例**：

```
📱 添加新账号
请输入图片文件路径: C:\Users\user\Desktop\qrcode.png
正在扫描二维码...

✓ 识别到账号信息：
  ─────────────────────────────────────
  服务提供商: GitHub
  账号:       user@example.com
  算法:       SHA1
  位数:       6
  周期:       30秒
  类型:       totp

分类 (直接回车使用默认): 工作
备注 (直接回车跳过, 最多 20 字): 公司账号

确认添加以下账号？
  ─────────────────────────────────────
  服务提供商: GitHub
  账号:       user@example.com
  分类:       工作
  备注:       公司账号
  ─────────────────────────────────────

确认添加？[Y/n]: y
✓ 账号添加成功！(ID: 1)
```

**支持的二维码格式**：
- `otpauth://totp/...`（标准 TOTP 格式）
- 不支持 HOTP、Steam 等非 TOTP 类型（会提示错误）

**查重机制**：
- 如果账号已存在（相同 issuer + account），直接提示
- 不进入填字段流程

**错误处理**：
- 文件不存在：提示"✗ 文件不存在！请检查路径。"
- 二维码识别失败：提示"✗ 未识别到有效的二维码！"
- HOTP 类型：提示"✗ 该二维码是 HOTP 协议，本工具仅支持 TOTP。"
- 账号已存在：提示"✗ 账号已存在: GitHub - user@example.com"

所有错误提示后会暂停，按 Enter 返回主菜单。

#### 3. 编辑账号

修改账号的分类和备注。

**操作流程**：

1. 选择 `3` 进入编辑账号
2. 显示账号列表
3. 输入账号编号
4. 显示当前信息
5. 输入新值（直接回车保持不变，输入 `.` 清空）
6. 确认修改

**示例**：

```
选择要编辑的账号（按分类分组）：

  [default]
      1. GitHub - user@example.com
      2. Google - user@gmail.com

输入账号编号 (0 取消): 1

当前信息：
  服务提供商: GitHub
  账号:       user@example.com
  分类:       default
  备注:       (空)

输入新值（直接回车保持不变，输入 . 清空）：
  分类 [default]: 工作
  备注 []: 公司账号

✓ 更新成功！
  分类: default → 工作
  备注: (空) → 公司账号
```

**特殊输入**：
- 直接回车：保持原值不变
- 输入 `.`：清空字段（分类清空后回 default）

**限制**：
- 只能修改分类和备注
- 不能修改 issuer、account、secret 等核心字段

#### 4. 删除账号

删除账号（不可恢复）。

**操作流程**：

1. 选择 `4` 进入删除账号
2. 显示账号列表
3. 输入账号编号
4. 显示账号信息
5. 输入确认短语（必须完全匹配）

**确认机制**：

```
确定要删除以下账号吗？
  服务提供商: GitHub
  账号: user@example.com

⚠️  此操作不可恢复！
请输入以下内容确认删除：
  YES, delete GitHub - user@example.com

>>>
```

**确认规则**：
- 必须完整输入 `YES, delete <issuer> - <account>`
- 大小写敏感
- 不匹配则取消

**错误处理**：
- 无效编号：提示"✗ 无效的选择！"，按 Enter 返回主菜单
- 非数字输入：提示"✗ 请输入数字！"，按 Enter 返回主菜单
- 确认短语不匹配：提示"已取消。"

#### 5. 导出备份

导出所有账号到 JSON 文件。

**操作流程**：

1. 选择 `5` 进入导出备份
2. 输入导出路径（直接回车使用默认路径）
3. 确认覆盖（如果文件已存在）
4. 导出成功

**默认路径**：
- `~/.mini2fa/backups/mini2fa_backup_<时间戳>.json`

**备份文件内容**：
```json
{
  "version": 1,
  "exported_at": "2026-08-14T23:00:00",
  "master_key": {
    "salt": "...",
    "nonce": "...",
    "encrypted_key": "...",
    "hint": "...",
    "version": 1
  },
  "accounts": [
    {
      "issuer": "GitHub",
      "account": "user@example.com",
      "secret_encrypted": "...",
      "algorithm": "SHA1",
      "digits": 6,
      "period": 30,
      "category": "default",
      "notes": ""
    }
  ]
}
```

**跨机器迁移**：
- 备份文件内嵌主密钥（master_key）
- 在另一台机器导入时需要输入备份对应的主密码
- 导入后本机密码变为备份的主密码

**错误处理**：
- 路径为空：提示"✗ 路径不能为空！"
- 文件名非法字符：提示"✗ 文件名包含非法字符"
- 文件已存在：提示覆盖确认
- 导出失败：提示"✗ 导出失败: ..."

#### 6. 导入备份

从 JSON 文件导入账号。

**操作流程**：

1. 选择 `6` 进入导入备份
2. 输入备份文件路径
3. 如果是跨机备份，输入备份对应的主密码
4. 预览导入内容
5. 确认导入
6. 冲突账号逐个询问

**导入三态**：

| 情况 | 处理方式 |
|------|---------|
| 本机空库 + 跨机备份 | 先采用备份主密钥，再原样入库 |
| 本机已有账号 + 跨机备份 | 用备份密钥解密重加密，本机密码不变 |
| 同机备份 | 直接用当前密码解密 |

**预览**：

```

────────────────────────────────────────────────────────────
  将导入（2 个）：
    ✓ GitHub - user@example.com
    ✓ Google - user@gmail.com
  已存在（1 个）：
    - AWS - admin@company.com
  损坏无法导入（0 个）：
────────────────────────────────────────────────────────────
  共 3 个，将导入 2 个
```

**冲突处理**：

```
以下 1 个账号在库中已存在，请选择使用哪个版本：
  AWS - admin@company.com
    用当前的还是备份的？[当前/备份，默认当前]: 备份
```

**导入结果**：
```
✓ 导入完成：新增 2 个，保留当前 1 个
```

**错误处理**：
- 路径为空：提示"✗ 路径不能为空！"
- 文件不存在：提示"✗ 文件不存在！"
- 文件格式错误：提示"✗ 导入失败：备份文件格式错误"
- 备份主密码错误：提示"✗ 备份主密码错误！"
- 备份文件损坏：提示"✗ 导入失败：无法解密备份文件"

#### 7. 修改主密码

修改主密码和密保提示。

**操作流程**：

1. 选择 `7` 进入修改主密码
2. 验证旧密码（最多 3 次）
3. 输入新密码（满足强度要求）
4. 确认新密码
5. 设置新的密保提示（可选）
6. 执行修改

**密码强度要求**：
- 长度 ≥ 6 位
- 必须包含大写字母、小写字母和数字

**修改特性**：
- 修改后旧密码立即失效
- 数据库中的密文不变（只重加密主密钥）
- 验证失败不污染当前会话

**错误处理**：
- 旧密码错误 3 次：提示"✗ 验证失败次数过多，程序将退出"，停留 1.5 秒自动退出
- 新密码不满足要求：提示具体错误，剩余尝试次数
- 两次密码不一致：提示"✗ 两次密码不一致！"
- 设置失败 5 次：提示"✗ 主密码设置失败"，停留 1.5 秒自动退出

## 命令行模式

命令行模式提供零交互接口，供 Agent 和脚本使用。

### 设计原则

1. **零交互**：所有参数通过命令行传入，无任何提示词
2. **只读接口**：只提供 `list` 和 `get`，不提供管理功能
3. **简洁输出**：默认输出人类可读格式
4. **密码安全**：密码通过 `-p` 参数传入，不残留在环境变量

### list 命令

列出所有账号（ID + 服务商 + 账号）。

**语法**：
```bash
mini2fa list -p <password>
```

**参数**：
- `-p, --password`：主密码（必需）

**输出示例**：

```
  [default]
      1. GitHub - user@example.com
      2. Google - user@gmail.com

  [工作]
      3. AWS - admin@company.com
```

**输出格式**：
- 按分类分组
- default 分组排最前
- 其余分类按名称排序
- 编号右对齐（3 位）

**错误处理**：
- 密码错误：`密码错误`（exit code 1）
- 无账号：`暂无账号`（exit code 0）
- 缺少参数：`错误: 缺少密码参数，请使用 mini2fa list -p <password>`（exit code 1）

### get 命令

根据账号 ID 获取验证码。

**语法**：
```bash
mini2fa get -p <password> <id>
```

**参数**：
- `-p, --password`：主密码（必需）
- `<id>`：账号 ID（从 `list` 命令获取，必需）

**输出示例**：
```
GitHub - user@example.com: 123456 (15s)
```

**输出格式**：
- `<issuer> - <account>: <code> (<remaining>s)`
- `code`：6 位验证码
- `remaining`：剩余有效秒数

**错误处理**：
- 密码错误：`密码错误`（exit code 1）
- 账号不存在：`账号不存在: <id>`（exit code 1）
- 缺少参数：`错误: 缺少密码参数，请使用 mini2fa get -p <password> <id>`（exit code 1）

### 使用场景

#### 场景 1：Agent 获取验证码

```bash
# 1. 列出账号，获取 ID
mini2fa list -p MyPassword123

# 2. 获取验证码（ID=1）
mini2fa get -p MyPassword123 1
```

#### 场景 2：Python 脚本调用

```python
import subprocess
import re

def get_totp_code(account_id: int, password: str) -> str:
    """获取 TOTP 验证码"""
    cmd = ['mini2fa', 'get', '-p', password, str(account_id)]
    result = subprocess.run(cmd, capture_output=True, text=True)

    if result.returncode != 0:
        raise Exception(f"Error: {result.stderr}")

    # 从输出中提取验证码（6位数字）
    match = re.search(r': (\d{6}) \(', result.stdout)
    if match:
        return match.group(1)
    raise Exception(f"Failed to parse code from: {result.stdout}")

# 使用
code = get_totp_code(1, "MyPassword123")
print(f"验证码: {code}")
```

#### 场景 3：管道操作

```bash
# macOS：复制验证码到剪贴板
mini2fa get -p MyPassword123 1 | pbcopy

# Windows：复制验证码到剪贴板
mini2fa get -p MyPassword123 1 | clip

# Linux：复制验证码到剪贴板
mini2fa get -p MyPassword123 1 | xclip -selection clipboard
```

## 安全说明

### 密码安全

**主密码强度要求**：
- 长度 ≥ 6 位
- 必须包含大写字母、小写字母和数字

**建议**：
- 使用强密码（12 位以上，包含特殊字符）
- 不要使用常见密码
- 定期更换密码
- 设置密保提示（但不要泄露密码）

**密码存储**：
- 主密码通过 PBKDF2-SHA256（600k 迭代）派生密钥
- 派生密钥加密随机生成的 master_key
- master_key 加密每个账号的 secret
- 修改密码只重加密 master_key，数据库密文不变

**命令行密码风险**：
- `-p` 参数会在命令历史中可见
- 建议在脚本中使用环境变量或配置文件
- 不要在共享环境中使用命令行模式

### 备份安全

**备份文件内容**：
- 所有账号信息（issuer、account、secret_encrypted）
- 主密钥文件（salt、nonce、encrypted_key）
- 主密码提示（明文）

**备份文件安全**：
- 备份文件仍需主密码才能解密
- 妥善保管备份文件，不要泄露
- 不要将备份文件提交到版本控制

**跨机器迁移**：
- 备份文件内嵌主密钥
- 在另一台机器导入时需要输入备份对应的主密码
- 导入后本机密码变为备份的主密码

**数据目录**：
- `~/.mini2fa/`：数据目录
- `~/.mini2fa/mini2fa.db`：SQLite 数据库
- `~/.mini2fa/master.key`：主密钥文件
- `~/.mini2fa/backups/`：备份目录

## 错误处理汇总

### TUI 模式错误

| 场景 | 错误提示 | 处理方式 |
|------|---------|---------|
| 密码错误 3 次 | ✗ 密码错误次数过多，程序将退出 | 停留 1.5 秒自动退出 |
| 首次设置密码失败 5 次 | ✗ 主密码设置失败 | 停留 1.5 秒自动退出 |
| 数据库损坏 | ✗ 数据库损坏或操作失败 | 停留 1.5 秒自动退出 |
| 文件不存在 | ✗ 文件不存在！请检查路径。 | 按 Enter 返回主菜单 |
